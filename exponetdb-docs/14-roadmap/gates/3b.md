## 2. Standards audit

**[OBSERVED]** (2026-10-06, before implementation; sources fetched from the
official sites.)

| Standard | Version found | Notes |
|---|---|---|
| MCP specification | 2026-07-28 (final, newest final release) | A later `draft` revision exists; its authorization pages match 2026-07-28 except that the client-registration example uses `http://[::1]:3000/callback` instead of `http://localhost:3000/callback`. No delta to frozen contracts or to this design. |
| OAuth 2.1 | `draft-ietf-oauth-v2-1-16` (2026-09-03), Internet-Draft | Not an RFC; documented as a draft. |
| Client ID Metadata Document | `draft-ietf-oauth-client-id-metadata-document-02` (2026-07-06), Internet-Draft | Not an RFC. Requires no redirects, refusal of RFC 6890 special-use addresses, simple string comparison of the URL, no shared-secret auth methods; recommends a 5 KB read limit (the order sets 64 KiB, §5 D3). |
| RFC 8414, 8707, 9207, 9728, 7009, 8252, 7523, 7591, 8628, 9700 | published RFCs | unchanged |

Consequences recorded before implementation:

- MCP 2026-07-28 requires an authorization server to provide **at least
  one** of RFC 8414 metadata or OpenID Connect Discovery, and clients try
  RFC 8414 first. OIDC Discovery 1.0 requires `jwks_uri`,
  `subject_types_supported` and `id_token_signing_alg_values_supported`,
  which ExponetDB (no ID tokens, no OIDC) cannot state truthfully. ExponetDB
  therefore does not serve `/.well-known/openid-configuration` (§5 D2).
- `iss` in the authorization response is a SHOULD in MCP 2026-07-28 and
  RFC 9207; ExponetDB returns it on every authorization response, errors
  included, and advertises `authorization_response_iss_parameter_supported`.
