# TC-011 `backup.verify` never detects corruption

Verdict: PARTIAL. Corruption that pgBackRest reports is now counted and fails the run; a deleted WAL segment is not reported by pgBackRest 2.60 and still passes; the catalog never records WAL gaps.

## Real engine, shipped helper (pgBackRest 2.60.0, encrypted repository, scripts `t11r1.sh`, `t11scoped.sh`, `t11gap*.sh`; whole-repository verify unless stated)
| case | old helper | new helper |
|---|---|---|
| clean repository | succeeded, 0 | succeeded, 0 |
| 16 bytes flipped in a WAL segment (a stop/start segment of a backup, or any) | `succeeded`, `verifyErrors 0` (excerpt shows `invalid result .. status: error`) | `failed`, `verifyErrors 3` |
| truncated WAL segment | succeeded, 0 | failed, 3 |
| corrupt backup file (whole repo and label-scoped) | succeeded, 0 | failed, 4 |
| deleted backup file | succeeded, 0 | failed, 4 |
| deleted WAL segment (a middle one, the last one, the newest backup's stop segment) | succeeded, 0 | **succeeded, 0** (pgBackRest says `status: ok`, backup `valid`) |
Label-scoped verify (the only form the Control Plane runs, `POST /clusters/{id}/backups/{id}/verify`): corrupt STOP or START segment of that backup: `failed`, 3; corrupt LAST archived segment after the backup: `succeeded`, 0 (outside the backup's scope).
Restore of the backup whose stop segment was deleted: `FATAL: WAL ends before end of online backup`; `restore.prepare` showed `walContinuous null, refusals []`.

## Control Plane level (probe `r1-cp-backup.host.test.ts`)
Corrupt stop segment of the newest backup then `POST /clusters/{id}/backups/{id}/verify`: new `verification_failed`, catalog verification `failed`; old `succeeded / passed`, catalog `passed`. A clean repository: all three backups `succeeded / passed`.

## Acceptance
Go unit tests (clean, corrupt segment, deleted segment, invalid backup, error without counts) pass; the finding's `pglab` cases with a real corrupted and a real deleted segment were not run by the fix. The "deleted segment" half cannot pass against real pgBackRest 2.60 (above). See findings "backup.verify passes a repository with a deleted WAL segment" and decision D-R1-2.

## Diff review
`pgbrVerify` sums the counts under each archive/backup, else counts `status: error|invalid` lines and `invalid result` warnings; `verifyErrors > 0` ends the run `failed`. The Control Plane already required `succeeded` and `verifyErrors == 0`. No change to the CP.
