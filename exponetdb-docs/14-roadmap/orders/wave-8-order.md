## 1. Mission

Build **Wave 8** of ExponetDB: the complete Web App, on a real design system,
so that a person can steer the whole fleet comfortably and beautifully from the
browser — the way Supabase Studio makes a database comfortable — within
ExponetDB's own model (targets, environments and tiers; plans, apply, verify;
approvals; nodes; audit).

Concretely:

1. Replace the minimal vanilla-TypeScript Web App (`apps/web`, 14 routes, 3,502 LOC) **completely**. Its mock UI/UX is discarded. Nothing of its look is kept; **every security behavior, every URL contract and every browser test of it is kept** (Appendix C).
2. Build the design-system packages the docs already name: `packages/tokens`, `packages/ui`, `packages/ui-patterns`, `packages/ui-data`, `packages/icons`, and the app `apps/design-system`.
3. **Adopt Supabase's UI source** for those packages and for the page layouts the owner likes (the OAuth/MCP **Authorize** screen to about 95% in design and structure, the shell, the forms, the "create" flows) under the license procedure of §6. This is a deliberate, permanent exception to ADR-0017, made by the owner's order; §3 D2 and Phase 0 make the documents say so before any copy is made.
4. Build every screen of the information architecture (global, target, cluster and node levels, plan review, approvals, SQL, schema browser, migrations timeline, connections and locks, infrastructure, access, audit, settings), plus the additive server endpoints those screens need (§9).
5. Stop at **G8**. Do not deploy anything unless the owner asks.

The wave is large (the owner expects 200,000+ lines including tests, docs, CSS and the design-system app). **Size is a consequence, not a target**: quality gates (§11) decide whether it is done, not line counts.

**G7 is not yet accepted by the owner, who is working on that in parallel. Ignore that: it does not block this wave.** Do not edit `gates/7.md`, do not claim anything about G7, and fetch `origin/main` before every phase because Wave 7 follow-ups may still land there. (The G7 box "approval links land on the plan review page" is delivered by this wave; note it in `gates/8.md`, do not tick G7.)

## 4. Orchestration and the model policy

You are the **orchestrator**. You plan, integrate, run the checks, review diffs, write the gate record and commit. The volume of implementation goes to **subagents** (the `Agent` tool).

**Model policy for subagents [OWNER]: in about 99% of cases use Sonnet 5.5 or Haiku 5.5. Use Opus 5.5 only for a small number of extremely important feature implementations.** Always pass `model` explicitly (`"sonnet"`, `"haiku"`, `"opus"`); never rely on inheriting the parent's model.

| Tier | Use for |
|---|---|
| **Haiku 5.5** | mechanical, well-specified, low-risk work: bulk copy with the provenance header, renames and import rewiring, snapshot/story scaffolding, test-file scaffolding from a given pattern, docs index generation, grep sweeps, lint/format fixes, message-key extraction, filling a register table. Never for anything touching auth, sessions, CSRF, CSP, authorization, untrusted-content rendering or licensing decisions. |
| **Sonnet 5.5** (default) | components, screens, hooks, data layer, tests, design-system pages, server endpoints that do not change an authorization decision, routine reviews. |
| **Opus 5.5** (allowlist, each use logged) | (1) ADR-0030 and the C-2 amendment text and the license-procedure wording; (2) server: SPA fallback, asset loader, CSP/headers, session/CSRF/reauth client and its query-serialization; (3) the security-bearing screens: OAuth consent/Authorize, device, step-up, credentials, approvals and the **plan review page**, the typed-confirmation ladder, apply/verify flow, reveal-once secrets, break-glass, raw statement view; (4) the SQL section's live classification display and untrusted-deep-link handling, and the Monaco/CSP spike conclusion; (5) additive endpoints that decide who may see or do something (audit chain, query history/saved queries ownership, grant use); (6) the independent **adversarial reviews** at the end of Blocks B, C and D and the final G8 review, including a sample per-file license review of the copy register. |

Rules:

- **Log every Opus spawn** in `gates/8.md` §5 "Model use": phase, task, why Sonnet was not enough. If the log has more than a couple of dozen Opus entries by the end, the policy was broken; say so in the record.
- **Disjoint file ownership.** Give each parallel subagent a directory it exclusively owns. Shared files (root and package `package.json`, `bun.lock`, `tooling/boundaries/graph.json`, the route tree, `tsconfig*`, generated files, `CLAUDE.md`, shared docs) are edited only by you.
- **Subagents never commit or push.** They return a summary (files changed, commands run, results, open problems). You review the diff, run the checks of §11, fix or reject, then commit with the correct identity.
- **Self-contained prompts.** A subagent does not see this file. Paste into its prompt: the ground rules that apply (§2), the exact scope and target paths, the source files to read, the provenance-header rule (§6), the truthful-state and untrusted-content rules, the tests it must add, what it must not touch, and the required return format.

- **Parallelism.** Within a phase, fan out by package/screen. Between phases, the dependency order of §10 holds. Use `isolation: "worktree"` for large copy jobs if it avoids conflicts.

## 5. What exists today (facts to build on; all re-verify before relying on them)

### 5.1 `apps/web` (to be replaced)

- Vanilla TypeScript, one ES module bundle (`Bun.build`), one stylesheet, one HTML page. No router (`switch (pageOf(location.pathname))` over a fixed page list in `src/safe.ts`, duplicated as `WEB_PAGES` in `apps/server/src/interfaces/http/web.ts`; no test ties them). Every navigation is a full page load. Files: `main.ts`, `shell.ts`, `api.ts`, `dom.ts`, `safe.ts` (168), `reauth.ts`, `webauthn.ts` (uses `@simplewebauthn/browser` 14.0.0), `review.ts` (388, the plan-review rendering), `pages/{login,enrollment,account,approvals,consent,stepup,credentials,admin}.ts`.
- Unit tests only for `safe.ts` (13 cases) and `review.ts` (7 cases; hand-faked `document`). No DOM or component test tooling exists.
- Pages and routes: `/login`, `/setup` `/invite` `/recover` (`#token=` one-time links), `/account`, `/approvals` (`#operation=op_…`), `/step-up#id=stu_…`, `/credentials#cluster=cls_…&role=…`, `/oauth/consent#request=exar_…`, `/oauth/device`, `/oauth/error?reason=`, `/admin/clients`, `/admin/service-accounts`.
- Security behavior and DOM hooks: Appendix C.

### 5.2 How `serve` serves it (`apps/server/src/interfaces/http/web.ts`, `composition/access.ts` `loadWebAssets`)

- One `GET` per fixed page returns `index.html`; **no wildcard / SPA fallback**; unknown paths return the `NOT_FOUND` problem JSON (pinned by `http.test.ts` and `tooling/smoke/roles.sh`, which also expects `/api/v1/clusters/…/backups` → 404).
- Assets: **flat** `readdir` of the web directory (`/app/web` in the image); only `.html .js .css .svg` with names matching `^[a-z0-9][a-z0-9._-]{0,63}$`; everything else (subdirectories, uppercase hashes, `.woff2`, `.map`, `.wasm`, `.ico`, `.json`) is silently dropped. All files are held in memory and copied per request; no ETag, no compression.
- Headers on every page and asset: `cache-control: no-store`; `content-security-policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`; COOP/CORP same-origin; `permissions-policy` (publickey-credentials-get/create self, camera/microphone/geolocation off); `referrer-policy: no-referrer`; `nosniff`; `x-frame-options: DENY`. Pinned by `http-auth.test.ts` (`script-src 'self'`, no `unsafe-`, no `*`, no `http(s):`) and `http-auth.int.test.ts` (no `unsafe-inline`); all browser suites assert **zero CSP console violations**. No `font-src` or `worker-src` today (they fall back to `'none'` / `script-src`).
- Cookies (`packages/auth/src/sessions.ts`): `__Host-exdb_session` (HttpOnly, Secure, SameSite=Strict, 12 h absolute, 30 min idle), `__Host-exdb_csrf` (readable), `__Host-exdb_ceremony`, `__Host-exdb_oauth`. A cookie-authenticated mutation needs exact `Origin` = `EXPONETDB_PUBLIC_URL`, `Sec-Fetch-Site: same-origin`, and `x-csrf-token` equal to the CSRF cookie. **The session secret and CSRF token rotate on every re-authentication**; a stale cookie answers `SESSION_EXPIRED`. A cookie plus an `Authorization` header is `AMBIGUOUS_CREDENTIALS`. Hazard for a query-cache SPA: parallel in-flight requests around a step-up would bounce to `/login`. The client must read the CSRF cookie fresh on every request and serialize/pause requests around re-authentication.
- Dev: the exact-`Origin` check and `__Host-` cookies mean a Vite dev server must run at (or be proxied as) the configured public origin (`http://localhost:<port>` counts as secure).

## 6. What Supabase gives us, and the copy procedure

Source: `davdxpx/supabase`, commit **`8b9af568`** (attach it read-only with `add_repo` if it is not in the session; the earlier audit used `cc31e2bd`, so re-read what you copy). Root license **Apache-2.0** (`LICENSE`; the only copyright line is the appendix boilerplate "Copyright 2024 Supabase"). `packages/ui`, `ui-patterns`, `config`, `common` declare `"license": "MIT"` in `package.json` but have **no LICENSE file**; there is **no NOTICE**. shadcn/ui-derived files (MIT, "Copyright shadcn") carry **no notice**; one file carries a Facebook MIT header (`ui-patterns/src/SimpleCodeBlock/SimpleCodeBlock.tsx:4`, do not copy). So the governing license per file is ambiguous; the procedure complies with the superset.

### 6.1 Procedure (becomes ADR-0030)

1. **Copy only files on the allowlist** of §6.2 into ExponetDB's own packages. Never `vendor/`, never a workspace link, never sync. After the copy the file is ExponetDB's code and is edited freely.
2. **Header on every copied file** (first lines; CSS/MDX equivalent):
   `// Derived from supabase/supabase <source path> @ 8b9af568. Apache-2.0 (Copyright 2024 Supabase); package declared MIT. Modified for ExponetDB.`
3. **Register** each copied file in `exponetdb-docs/11-ui/third-party-register.md`: ExponetDB path | source path | source commit | license basis | notices applied | changes | review status. A small check (`tooling/checks/third-party.ts`, added to `bun run verify`) fails if a file with the header is missing from the register, a registered file is missing, or a file lacks the header. This is a **license-compliance register** (Apache-2.0 §4 requires the license text, retained notices and prominent change notices; G8 requires a recorded review) — not a runtime provenance layer; say so in ADR-0030 because the owner rejected a central notices layer on 2026-10-05.
4. Ship `LICENSES/Apache-2.0.txt` and a `THIRD_PARTY_NOTICES.md` naming Supabase (Apache-2.0 and the MIT declaration), shadcn/ui (MIT), Radix color scales if copied, and every other third-party derivative. Keep OFL license files with the self-hosted fonts.
5. **File-specific review before the first commit of a copy:** header, package declaration, repository license, third-party notices inside the file, trademark/brand content, fonts/images referenced, dependencies pulled in. Record the result in the register row. Unclear case → `[OPEN: OD-n]` for the owner; do not guess. (This is not legal advice.)
6. **Abort criterion (from the Wave 8 row):** a review that finds copied code without a clear license, or with obligations the owner does not accept → replace it with a native rewrite before release.
7. After the copy, run the dependency license scan (none exists today; add one — CI has only `bun audit`).

## Appendix C — What the rebuild must preserve (parity oracle)

**Security behavior**

- One-time links (`/setup`, `/invite`, `/recover`): token read from `#token=` only, prefix matched to the page (`exsu_`, `exiv_`, `exrc_`), removed from address bar and history (`history.replaceState`) **before** the redeem call, never logged; progress only in `sessionStorage['exdb.enrollment']` (never the token); the server keeps the ceremony in `__Host-exdb_ceremony`; TOTP QR drawn locally from the server's matrix (no image library, no remote QR); recovery codes shown once and `#codes-stored` gates `#continue`.
- `returnTo` is an **exact allowlist** (`safe.ts`: `/account`, `/oauth/device`, `/admin/clients`, `/admin/service-accounts`; `/oauth/consent#request=exar_<43>`; `/approvals[#operation=op_<26>]`; `/step-up#id=stu_…`; `/credentials#cluster=cls_…[&role=observer|reader|verifier|operator|migrator]`), fallback `/account`; recovery sessions always go to `/account`; the server never interprets `returnTo`. Extend it for new routes without ever making it a prefix match; keep the hostile-case tests.
- OAuth: `__Host-exdb_oauth` binding (HttpOnly, sent automatically, page never touches it); `POST /auth/oauth/consent/view` and `/auth/oauth/consent`; handle only from the fragment; the device code is typed by the person, never taken from a link; `/oauth/error?reason=` shows fixed text and never echoes the query; no remote logo; client name is untrusted text with "name not verified" unless first party; lookalike warning (`#lookalike`), redirect host (`#consent-redirect`), lethal-trifecta warning (`#trifecta-warning`), scope effect badges, tier boxes with a production acknowledgement, production write / human-only authority needs a proof ≤ 5 minutes.
- CSRF: read `__Host-exdb_csrf` fresh on every request (it rotates at re-authentication), validate `^[A-Za-z0-9_-]{1,128}$`, send `x-csrf-token`; same-origin only; never an `Authorization` header from the SPA.
- `withReauth`: on `REAUTH_REQUIRED` open the re-auth dialog (`#reauth-passkey`, `#reauth-totp`), then **retry the action once**; cancel maps to "Canceled. Nothing was changed."; pause/serialize other requests meanwhile.
- Untrusted text via text nodes only; invisible, bidi, tag and non-ASCII characters shown as `⟨U+202E⟩`-style code points in plan text; truncation notices; statement facts only for `up.sql`, never `verify.sql`; the full plan hash with a copy button; own-plan acknowledgement; agent-made-plan note (`#agent-note-<op>`); production framed distinctly.
- Write-only secrets: credentials page clears both fields before sending, 16 characters minimum, `withReauth`; API key secret shown once (`#api-key-secret`) and never rendered again; no `title`/`confirm()`; correct `autocomplete`/`inputmode`.
- `hashchange` forces a reload on fragment-bound pages (`/step-up`, `/approvals`, `/credentials`) so no form acts on the previous link's subject; `<meta name="referrer" content="no-referrer">`; `<noscript>`.
- Error display: server catalog message + stable code; fixed text for network/unknown errors; rate-limit text with retry time; exception text is never shown.
- External link contracts that the server, CLI and MCP emit: `/setup#token=`, `/invite#token=`, `/recover#token=`, `/step-up#id=stu_…` (`packages/auth/src/stepup.ts`), `/approvals#operation=op_…` (`packages/application/src/views.ts` `approvalUrl`; keep as a redirect to `/changes/plans/<id>`), `/credentials#cluster=cls_…&role=…` (CLI `exponetdb cluster credential submit`), `/oauth/consent#request=…`, `/oauth/device`, `/oauth/error?reason=`, `/login?returnTo=`.
