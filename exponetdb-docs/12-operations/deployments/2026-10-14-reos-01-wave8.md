## Release

**[OBSERVED]** The owner built the image on `reos-01` from a clean
`git archive` export of `ab6501e` with
`docker build --build-arg EXPONETDB_BUILD_COMMIT=ab6501e77af741fded612a7dcff8ae996bee6d1b`
(the CI `image` job's command), tagged it with its own ID, pushed it to the
loopback registry and set the tag and descriptions of `serve`, `worker` and
`gateway` and the image line of `exponetdb-migrate` (with `:`) in the Coolify
web interface. The session read all four back through the Coolify tools
before starting anything.

CI at the merge: the merged head `3153a24`'s run was still in progress when
the owner merged. The run before it (`5e5e772`) was green apart from the
visual baselines (fixed in `3153a24`) and the host scenario `journal`, which
fails identically on `main` (re-run of run 38469455446 at `d99c709`): a
Wave 5 node-agent defect, not this release's; no node agent is installed on
`reos-01` (G5 items 2 and 4 waived until one is).

additive bundle. Listing them in `frozen-bundles.json` belongs to the G8
acceptance.

## Rollback anchor

The image tag `sha256-456a47eb…` on the three roles **does not** return the
applications to Wave 7 by itself: the Wave 7 roles refuse readiness on the
newer ledger (`schema_newer`, as seen at 05:40:52). A return to Wave 7 is a
restore of the backup above (execution `lnbvzdyagz11zfriwpveh1yl`) together
with that image tag, and loses what was written after 05:39:09.
