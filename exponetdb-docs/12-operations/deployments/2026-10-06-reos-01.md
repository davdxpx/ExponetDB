## Configuration and operator commands

**[OBSERVED]** Each role holds only its own Control Store login and the keyring.
None has the PostgreSQL superuser password. All five `exdb_*` logins have
`rolsuper`, `rolcreatedb`, `rolcreaterole`, `rolreplication` and `rolbypassrls`
false. The migration resource holds only `exdb_migrate`, no keyring or runtime
role credentials, and its Compose definition sets `restart: "no"`.

Coolify's Docker Image deployment in this version does **not** pass the
`start_command` field to the container; without an override the image runs
its default `help` command. The runtime applications therefore use the supported
Custom Docker Options field:

```text
--entrypoint "node /app/bin/exponetdb.mjs worker"
--entrypoint "node /app/bin/exponetdb.mjs serve"
--entrypoint "node /app/bin/exponetdb.mjs gateway"
```

The effective container entrypoints were inspected. Non-null Compose entrypoints
clear the image's default `CMD`; all roles still use the identical image digest.

Operator commands require their **own minimal environment**; the role's full
`EXPONETDB_*` environment is intentionally rejected. For `control-store status`
and `audit verify`, supply only the runtime login URL and optional log settings
(no `exdb_migrate` login). `keyring status` additionally takes the keyring.
`bootstrap owner` takes the `exdb_serve` URL, public origin and optional RP ID,
without runtime role, installation, listener or keyring settings.

## Backups and restore

**[OBSERVED]** Coolify's database-only PostgreSQL backup runs
`pg_dump --format=custom --no-acl --no-owner`. An actual restore showed that it
loses the Control Store runtime grants (`control_store_permission_denied`).
That schedule was disabled. The active daily configuration is a **complete
`pg_dumpall` export of this dedicated PostgreSQL resource**, compressed with
gzip, which preserves roles and grants. It covers this resource's maintenance
and Control Store databases, never another Coolify database resource.

- Schedule UUID: `jw8pwd8gqufcl72y0iw7ewlx`; cron `0 2 * * *` in Coolify's scheduler timezone.
- Local retention: at most 14 backups, 14 days, 2 GB.
- Missing-backup threshold: two days.
- Verified execution: `soyphjt1iinpssh0gm6im21d`, success,
  69191 bytes.
- SHA-256 of the tested compressed dump:
  `93fb59cd57f86416dbf34b506faa2f90c56e47ef325b7749209e33c0b0c23151`.
- A protected copy is on the workstation, separate from the role passwords
  and keyring. This proves one off-server copy, **not** automated off-host delivery.
- The full dump includes SCRAM role verifiers and personal data once present;
  it is a secret backup artifact. It contains no plaintext role passwords or
  keyring material.

The actual full dump was restored into an isolated PostgreSQL 17 container,
initialized with a temporary superuser named `restore_admin` (so the dumped
`postgres` role does not collide). It was decompressed and fed to
`psql -U restore_admin -d postgres -v ON_ERROR_STOP=1`. No bootstrap SQL was
applied first: the complete dump creates its own roles and Control Store.
The release binary then ran `control-store status` and `audit verify` using
`exdb_serve`. The scratch container and temporary credential files were removed.
See the updated [restore runbook](../control-store-runbook.md#4-rb-10-control-store-down).
